# Техническое задание: Сервис интеллектуального нормоконтроля «НормоСкан»

## 1. Общее описание
Сервис предназначен для автоматизации проверки конструкторской документации (КД) на соответствие стандартам (ГОСТ, СТП) с использованием мультимодальных больших языковых моделей (VLM) и системы визуального RAG.

## 2. Архитектура и стек технологий
*   **VRAM:** Оптимизация под 16 GB (RTX 4080 / A4000).
*   **LLM/VLM:** Qwen2-VL-7B или Llama-3-Vision (в квантовании 4-bit/INT8).
*   **OCR:** EasyOCR или PaddleOCR (для точного извлечения мелкого текста).
*   **Vector DB:** Milvus или Qdrant (хранение эмбеддингов текстов ГОСТ и эталонных изображений).
*   **Backend:** Python, FastAPI, Celery (очередь задач), Redis.
*   **Frontend:** React/Streamlit для панели нормоконтролера.

---

## 3. Функциональные модули

### 3.1. Модуль препроцессинга и сегментации
*   Разбивка PDF на страницы.
*   Адаптивное изменение размера: основной поток — 512–800px по ширине.
*   **Интеллектуальный кроп:** Автоматическое выделение зон: «Основная надпись» (штамп), «Технические требования», «Спецификация», «Зоны графических видов».

### 3.2. Гибридный RAG (Text + Vision)
*   **Text RAG:** Поиск текстовых правил в базе ГОСТ по контексту страницы.
*   **Visual RAG:** 
    *   База данных «Галерея ошибок и эталонов». 
    *   При анализе узла (например, стрелка разреза) система ищет в БД похожие изображения.
    *   Если найден «паттерн ошибки» с высокой косинусной близостью, VLM получает подсказку: *«Данный элемент на 92% похож на ошибку типа 'Неверная засечка стрелки' из базы данных»*.

### 3.3. Модуль анализа и генерации JSON
*   Экстракция метаданных в JSON (Обозначение, Наименование, Материал, Масса, Литера).
*	Экстракция других технических метаданных (для формирования базы знаний об изделиях)
*   Сверка метаданных между листами одного комплекта (консистентность).

### 3.4. Очередь и менеджмент ресурсов
*   Приоритетная очередь задач.
*   Освобождение VRAM после каждого прохода страницы (использование `torch.cuda.empty_cache()` или специализированных инференс-движков типа `vLLM` / `SGLang`).

---

## 4. Реестр и Статистика
*   **База проверок:** Хранение истории (кто загрузил, когда, статус, найденные ошибки).
*   **Модуль аналитики:** LLM-ассистент, формирующий отчеты: *«В отделе №5 за месяц участились ошибки в оформлении допусков (ГОСТ 2.307)»*.

---

## 5. Программа и методика испытаний (Автоматические тесты)

Для обеспечения качества внедряются следующие уровни тестирования:

| Тип теста | Что проверяется | Инструмент |
| :--- | :--- | :--- |
| **Unit-тесты** | Корректность парсинга PDF, извлечение текста, работа кроппера. | `pytest` |
| **RAG Retrieval Test** | Точность поиска (Hit Rate) нужного ГОСТа или изображения-эталона. | `RAGAS` / `DeepEval` |
| **VLM Accuracy Test** | Сравнение вывода LLM с «золотым набором» (чертежи с заранее размеченными 100 ошибками). | `Ground Truth JSON` |
| **Load Test** | Стабильность очереди при 10 одновременных пользователях на 16 ГБ VRAM. | `Locust` |
| **Integration Test** | Полный цикл: Загрузка PDF -> JSON метаданные -> Отчет об ошибках. | `TestContainers` |

## 7. Нюансы реализации (Key Insights)
1.  **Контекстное окно:** При постраничном анализе в модель передается краткое резюме (Summary) предыдущих страниц (например, чтобы знать, что на Листе 1 был «Вал», и проверить, совпадает ли это на Листе 5).
2.  **Обратная связь:** В интерфейсе отчета у каждой ошибки есть кнопка «👍/👎». Отрицательные срабатывания автоматически уходят в папку для переобучения/корректировки Visual RAG.
3.  **Безопасность:** Весь инференс строго локальный (Localhost), никакие данные не отправляются на внешние API (OpenAI/Anthropic).

### Резюме по железу (16 GB VRAM)
Чтобы сервис не «падал»:
*   Использовать **4-bit AWQ/GPTQ квантование**.
*   Размер входного изображения для VLM ограничить логическими блоками (не всю простыню А1 сразу, а фрагменты, где есть текст/графика).
*   Параллелизм: 1 активный запрос на генерацию + фоновая подготовка (OCR/Векторизация) следующей страницы на CPU.
